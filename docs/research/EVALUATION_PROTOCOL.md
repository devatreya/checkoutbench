# Frozen evaluation protocol

1. Audit fixture/evaluator changes and run negative controls plus regression/browser checks. Freeze with `.venv/bin/python -m scripts.research.manage freeze`. The command is explicit and changes the release artifact; never refreeze in place after collecting a publication cohort. Increment release ID for design/source changes.
2. Independently review every scenario hash. Resolve disputes before publication. Run `review-packet`, have a human evaluate solvability/task/optional/auth/negative-control criteria, then `import-review`. Automated approvals are prohibited. Reviews are local attestations, not cryptographic identity verification.
3. Verify each exact local model using `python -m scripts.research.verify_models --model MODEL`. Official provenance and weight/config hashes, real cold/warm outputs, precision, quantisation, runtime and hardware are recorded. Missing exact weights fail closed.
4. Choose pilot repetitions and limits before starting. UI defaults (3 repeats, 100 actions, 180s, 8,192 output tokens, retry policy displayed) are pilot settings, not a statistically powered final protocol. Use pilot variance to preregister final repetition count; do not tune conditions after observing model failures.
5. Select Models → Benchmark Coverage → Review → Run All → Analyse. Review explicit total runs and unknown costs. Every model receives all 174 active tasks, seed 2026, scenario-default profile, standard mode, fresh browser sessions, sequential execution. Freeze release/hash and settings in every run. Different settings create different protocol hashes; analysis never silently pools them.
6. Preserve every attempt, infrastructure failure, timeout and stop. Completion mode and auth simulation are predefined. Normal Run All excludes sealed tests. Pause and stop retain partial evidence.
7. Export via Results or `manage export`. Verify SHA256SUMS, source hashes, exact definitions, checkpoint/runtime records and per-run outcomes. Claims require readiness review, independently reviewed data and sufficient independent coverage; passing reference tests is insufficient.
8. A separate custodian supplies an independently authored final corpus. `manage seal` records commitments; `reserve-final` atomically consumes a one-use reservation for frozen protocol/checkpoints. No ordinary preview/tuning route exists. The current release contains no final corpus and therefore makes no held-out generalisation claim.

Official test-mode evidence is separate. Existing Stripe/Shopify/Razorpay/Cashfree API checks are read-only connectivity/object checks. Optional `official_browser --stripe-session cs_test_...` verifies test mode and records hosted browser inspection; it does not claim completed payment validation. Full authenticated official workflows for all providers remain pending credentials and reviewed interaction evidence. Never use live keys, genuine cards/OTPs or government transactions.
