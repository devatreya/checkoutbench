# Benchmark validity audit — v3 measurement work

Audit baseline: commit `a052b5b`, all 74 v2.1 scenarios, nine environments. Passing regression tests establish software behavior only. Existing result JSON is retained without retroactive rescoring. `research/scenario-audit.json` inventories every scenario, its implementation lineage and risks.

| Severity | Evidence / code | Scientific impact | Correction | Verification |
|---|---|---|---|---|
| Critical | `backend/evaluator/v2.py:evaluate_v2` binary success includes safe abort/handoff | Payment completion claims can be false | Add separate preparation, resolution, handoff, simulated completion and safe-abort outcomes | Negative controls for premature abort, wrong fields/method, duplicate submission and handoff |
| Critical | `qr_recovery_accuracy` credits Q0/Q1/Q3 without recovery | Inflated recovery denominator and numerator | Record initial actual decoder validity; denominator only exposed, recoverable problems; require observed recovery and valid final QR | Clean-vs-degraded controlled checks |
| High | `payment_accuracy` folds selection, credentials and QR/auth state together | Cannot identify method-vs-detail errors | Separate method, detail, auth and final state measurements | Correct method/wrong card and wrong method/correct fields tests |
| High | `frontend/.../analysis.ts:stats` median includes failures | Not a successful-checkout latency | Separate preparation/resolution/failed durations | Mixed success/failure timing fixtures |
| High | v2.1 Q scenarios use different families by quality | QR quality confounded with provider | Same implementation QR matrix; independently crossed auth surface/fault/mode | Compare canonical scenario definitions excluding declared factor fields |
| Critical | `checkout_fixtures/v21.js` shared renderer and shared workflow engine | Nine labels are not nine independent websites | Conservative lineage clustering; separately authored implementations, implementation-level splits | Source hashes, architecture review and split-disjointness checks |
| Critical | Migrated V2H holdouts were regression-tested | No unseen evaluation claim is justified | Custodian-supplied independent corpus pending; public commitments and one-shot reservation tooling implemented | Preview/ordinary batch denial; immutable hash and consumption tests |
| Critical | No independent human ground-truth review | Reference solvability can agree with a buggy evaluator | Review registry keyed to scenario/implementation hashes; disputed or unreviewed cases block publication | Tamper/stale review rejection; human review remains pending |

No external reproduction, human review, official browser sandbox validation or model capability is inferred from this audit. The machine-readable readiness report is authoritative for remaining blockers.
