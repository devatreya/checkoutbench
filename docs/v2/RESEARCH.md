## Experimental attribution

A is a deterministic test user using native synthetic Link. It leaves incorrect native autofill unchanged, making stale saved data a deliberate negative control. B disables native Link and uses conventional card fields with the same customer/order objective. C permits Link and requires verification of prefill. B necessarily changes the available payment interaction, but not the underlying card-funding objective. Results pair only matching scenario, seed, profile, repetition, viewport and resource limits. A reference implementation in B/C is plumbing validation, never claimed AI benefit.

The reported user-interaction proxy counts reference user actions in A and independent authentication actions in B/C. It does not estimate mental effort. Wall time includes browser setup and evidence capture, as in v1. Native autofill fields and incorrect values are tracked separately from model actions. Error-detection latency is explicitly the interval from presented error to first recovery action, not a claim about the model's internal recognition time.

## Uncertainties and exclusions

Production styling, live provider eligibility, native wallet internals, live government policies, current government layouts and real authentication timing are not reproduced. QR damage results are independently decoded and tested rather than assumed from visual appearance. Holdouts validate only fixture solvability; no weights, prompts or model policies are trained/tuned against their outcomes. Optional real Shopify/Stripe sandbox integration and broader journey search are not enabled. Specialist adapters remain available but require genuine weights/endpoints before model evaluation.
